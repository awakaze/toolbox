# Steam 补充包工具箱（油猴脚本）

一个运行在 Steam 社区"补充包制作"页的 Tampermonkey 用户脚本：按**利润**筛选补充包，支持**拉黑 / 收藏 / 做包队列**管理，队列里的游戏可**每日自动做包**。价格全部取自**官方 Steam 接口**，并按 **Steam 新版市场手续费**（含低价商品固定费用）计算税后收入。

> v0.2 重写了整个查询层：不再依赖 priceoverview / item_nameid / 地区币种探测，统一走市场搜索接口。

## 功能特性

- **利润筛选**：逐游戏展示 做包成本 / 3 张卡牌税后收入 / 补充包税后卖价 / 利润率 / 制作量 / 上次制作
- **查询架构（v0.2）**：每游戏固定 **2 个请求**，全部走 `search/render?norender=1`（JSON，`sell_price` 为钱包币种**精确分值**，无需解析本地化价格字符串）：
  - 普通卡：等价于页面链接 `steamcommunity.com/market/search?appid=753&category_Game=app_X&category_cardborder=cardborder_0`（cardborder_0 天然排除闪卡，卡牌数 >10 自动翻页）
  - 补充包：等价于页面链接 `steamcommunity.com/market/search?appid=753&category_Game=app_X&category_item_class=item_class_5`
  - 一袋宝石价：`query=Sack of Gems` 同接口获取（30 分钟缓存）
- **利润计算（v0.2.2）**：手续费按"卖家到手价"精确反解（买家支付价 = 到手 + fee(到手)）；卡牌收入**逐卡单独计税后再平均**；打开页面不自动查询，点「查询当前列表」强制重查并使全部缓存（含宝石价）立即失效，缓存 30 分钟
- **利润保护**：默认**不做利润低于 10%** 的补充包；队列里对单个游戏勾选"强制"即可绕过阈值
- **列表管理**：未分类可在 拉黑 / 收藏 / 做包队列 之间流转，支持"一键拉黑未分类"
- **做包高度可定制**：`自动做包`开关 + `一键制作`按钮，两者都受利润闸门保护
- **每日自动做包**：记录每游戏`lastMade` + 读取 Steam 自身冷却，打开页面即自动补做，天然幂等
- **防风控（修复旧脚本"查询卡死"）**：所有价格请求**严格串行 + 可配间隔**，命中限流自动退避重试，单游戏失败即标记跳过、绝不卡死
- **跨页持久化**：列表、配置、价格缓存存浏览器端 GM 存储（`@grant GM_getValue`），刷新/换天保留

## 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/)（Chrome/Edge/Firefox）
2. 打开 Tampermonkey → 管理面板 → `+` 新建脚本
3. 全选粘贴 [steam-booster-tool.user.js](steam-booster-tool.user.js) 内容，保存
4. 登录 Steam 社区，打开补充包制作页，工具栏即出现在页面上

## 配置项（GM 存储，脚本内设置面板修改）

| 键 | 默认 | 说明 |
|---|---|---|
| `autoCreate` | `false` | 进入页面是否自动做包 |
| `profitThreshold` | `0.10` | 利润阈值（默认 10%） |
| `gemPriceSource` | `market` | `market` 市场宝石价 / `custom` 自定义 |
| `customGemPrice` | `270` | 自定义一袋宝石价（分） |
| `reqInterval` | `250` | 价格请求间隔 ms（防风控） |
| `maxRetries` | `3` | 单请求失败/限流重试次数 |
| `priceCacheTTL_min` | `30` | 价格数据存储有效期（分钟）；仅作数据存储，查询按钮点击即全量失效实时重查 |
| `forceList` | `{}` | 逐游戏强制制作映射 `{appid: 1}` |

> 查询行为：打开页面**不自动查询**；点「查询当前列表」= 全部缓存立即失效，**全量实时重查**（含宝石价）。

## 手续费模型（`sellerNet`）

Steam 新版市场规则：卖家设定**到手价 R**，买家支付 `P = R + fee(R)`；手续费按到手价计算，一笔交易拆两笔独立费用，各自**向下取整到分、且每笔不低于最低额**：

```
交易费 = max(minFee, floor(到手价 × 5%))     // Steam 交易费
分成费 = max(minFee, floor(到手价 × 10%))    // 卡牌/补充包属 Steam 本体
```

**【2025年12月起】单笔最低手续费提高为 $0.01 等值：国区 = ¥0.07**（旧值 ¥0.01 已失效）。实测校验（真实挂单数据）：到手 ¥0.60 → 买方支付 ¥0.74；到手 ¥0.85 → 买方支付 ¥1.00；国区最低挂单价 ¥0.21（7+7+7）。

脚本由市场返回的**买家支付价 P 精确反解到手价 R**（迭代求解 `R + fee(R) = P`），并逐卡单独计税后再取平均（手续费按笔非线性，先平均再算税会失真）。反解校验示例（人民币区，minFee=7 分）：

| 买家支付价 | 手续费 | 到手 | 验证 |
|---|---|---|---|
| ¥0.21 | 0.07+0.07 | ¥0.07 | 7+14=21 |
| ¥0.74 | 0.07+0.07 | ¥0.60 | 60+14=74 |
| ¥1.00 | 0.07+0.08 | ¥0.85 | 85+15=100 |
| ¥1.08 | 0.07+0.09 | ¥0.92 | 92+16=108 |

> 费率与最低费在脚本头部 `DEFAULT_FEE` 集中配置。`minFee: 7` 仅对人民币区实测成立，其他币种为各自 $0.01 等值，换钱包币种需改这一处。

## 常见问题

**Q：进页面后状态一直"正在读取补充包数据…"？**
脚本依赖页面全局 `CBoosterCreatorPage.sm_rgBoosterData` 异步加载；若持续无数据，刷新页面或确认 Tampermonkey 已启用并匹配当前网址。

**Q：为什么当前列表很久才出价格？**
为防 Steam 卡风控，脚本强制**串行 + 间隔**请求，列表越长越久（符合代价）。再次访问时多数价格走缓存会明显加快。请求间隔可在控制条调大/调小。

**Q：查询了一半某项标记失败/受限？**
命中 Steam 限流时脚本会退避重试，超限后标注并跳到下一游戏，**不会像旧脚本一样卡死**。可稍等后再点"查询当前列表"。

**Q：自动做包没做某些队列游戏？**
被跳过的通常是：冷却未过、利润低于阈值、或卡牌不可交易、或尚未算出利润。勾选该游戏"强制"可强制制作（若宝石充足）。
