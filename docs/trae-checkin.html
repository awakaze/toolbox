Trae 每日自动签到

自动完成 Trae CN（TraeWork）每日签到领取积分（每天 150~200 积分），以 Python 标准库为主。

Python pycryptodome（可选） 纯标准库可跑
查看源码 完整 README

功能特性

  • 自动读取本机登录态：默认从本机已登录的 Trae IDE 直接解密读取 token，无需手动复制（可选装 pycryptodome；未装则退回手动配置）
  • 先查后签：先查询签到状态，已签到自动跳过；领取后自动复查确认到账
  • 每日运行记录：本目录 checkin_history.jsonl 按日记录每次运行；计划任务重复触发（开机补跑）时若当天已签到成功则静默跳过，不发请求、不弹通知
  • 限流重试：针对高峰期服务器限流（code 9074）自动指数退避重试
  • 防风控限额：每日领取请求最多 10 次（状态查询不计入），跨多次运行累计，超限自动停止
  • 随机延迟：可配置启动后随机延迟 0~N 分钟，避开整点脚本高峰
  • 多账号：支持批量签到，按账号逐个处理、汇总结果
  • 通知推送：失败时推送 Server酱（微信）/ Bark（iOS）/ Telegram / 自定义 Webhook；TG 自动使用系统代理
  • Windows 系统通知：失败必弹；成功仅当天首次成功弹一次，之后的重复触发静默（无窗口弹出，零依赖）
  • 计划任务后台运行：定时触发时经 pythonw 完全后台运行，无黑窗口、无闪烁
  • token 有效期检测：JWT 格式的 token 自动显示剩余天数，临期预警、过期明确报错
  • 安全：日志中 token 脱敏，请求头与官方客户端行为一致

快速开始（本机部署）

1. 获取 token

默认自动读取：脚本优先从本机已登录的 Trae IDE 解密出账号 token，本机登录过 Trae 即可直接跑，无需手动复制。

自动读取依赖 pycryptodome（可选）。已装则自动启用；未装也能跑，只是需要手动配置 token：pip install pycryptodome

2. 填写配置

复制 config.example.json 为 config.json（与脚本同目录）即可，TRAE_TOKEN 留空也能自动读取本机登录态：

{
  "TRAE_TOKEN": "",
  "CHECKIN_MAX_DELAY": "300"
}

config.json 含 token，已被本目录 .gitignore 忽略，不会提交到 git；仓库内只保留模板 config.example.json。云服务器上无法读取本机登录态，需填 token。

3. 运行

Windows：双击 run_checkin.cmd，窗口会显示结果后暂停。

macOS / Linux：

./run_checkin.sh

日志自动写入同目录的 checkin.log。

4. 设置每天自动签到

# Windows（任务计划程序，无需管理员权限，每天 08:00）
schtasks /create /tn "TraeCheckin" /tr "\"C:\你的路径\run_checkin.cmd\"" /sc daily /st 08:00

# macOS / Linux（crontab -e 添加）
0 8 * * * /你的路径/run_checkin.sh

配置项说明

配置文件 config.json 与环境变量通用（环境变量优先），全部键：

键必填说明
TRAE_TOKEN选填手动指定单账号 token；留空则自动读取本机 Trae 登录态
TRAE_TOKENS选填多账号，逗号分隔，支持命名：主号=token1,小号=token2
CHECKIN_MAX_DELAY否启动随机延迟上限秒数（默认 0，定时任务建议 300）
TRAE_RETRIES否失败重试次数（默认 5）
NOTIFY_ON_SUCCESS否签到成功是否推送第三方通知，1/0（默认 0）
SERVERCHAN_KEY否Server酱 SendKey，推送到微信
BARK_URL否Bark 推送地址，如 https://api.day.app/你的key
TG_BOT_TOKEN否Telegram Bot Token（需配合 TG_CHAT_ID）
TG_CHAT_ID否Telegram Chat ID
WEBHOOK_URL否自定义 Webhook，POST JSON {"title","content"}
LOG_FILE否日志文件路径

命令行用法

python3 trae_checkin.py                  # 正常签到
python3 trae_checkin.py --status-only    # 只查状态，不领取（不写运行记录、不弹通知）
python3 trae_checkin.py --retries 10     # 失败最多重试 10 次
python3 trae_checkin.py --max-delay 300  # 随机延迟 0~5 分钟后开始
python3 trae_checkin.py --delay 120      # 固定延迟 2 分钟后开始（计划任务触发用）
python3 trae_checkin.py --scheduled      # 计划任务模式：当天已签到成功则静默跳过
python3 trae_checkin.py --no-notify      # 本次不推送通知
python3 trae_checkin.py -v               # 调试日志（含接口原始响应）
python3 trae_checkin.py --config /path/to/config.json  # 指定配置文件

退出码：0 全部成功 / 1 存在失败 / 2 配置错误。

Windows 定时任务容错

用任务计划程序实现每天自动签到，内置四层本地容错：

场景保障
到点没开机StartWhenAvailable：下次开机登录自动补跑
跑到一半断电 / 关机LogonTrigger：当天再次开机登录 2 分钟后自动补签（服务端幂等，已签自动跳过）
程序卡死 / 异常退出RestartOnFailure：5 分钟后自动重启，最多 3 次
请求被限流（9074）脚本指数退避重试（默认 5 次），重试耗尽才判失败
重复触发弹通知扰民本地 checkin_history.jsonl 记录当天结果：已成功则后续触发静默跳过

导入任务（无需管理员）：

schtasks /create /tn "TraeCheckin" /xml "C:\trae-checkin\TraeCheckin.xml"

导入前需编辑 TraeCheckin.xml，把 <Command> 里的路径改成实际的 run_checkin.cmd 完整路径。

常见问题

提示 token 无效或已过期（code 1001）？

token 有有效期，过期后重新获取一次，更新到 config.json 即可。

提示服务器繁忙（code 9074）？

高峰期限流，属正常现象。脚本会自动重试；也可把定时任务改到凌晨等低峰时段。

提示参数错误（code 9004）？

用 -v 参数运行查看接口原始响应，确认 token 是否完整复制（注意不要带上多余空格或换行）。

签到显示成功但没收到通知？

检查通知渠道配置是否完整（如 Telegram 需要同时配 TG_BOT_TOKEN 和 TG_CHAT_ID，国内网络需系统代理在线）。
